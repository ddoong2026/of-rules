# 역사 탐구 교실 구현 현황

기준: 2026-09-15. 기능과 시각 콘텐츠를 구현 중인 개발본입니다. 전체 역사 고증과 실제 학급 연결이 완료되지 않아 운영 수업 시작은 서버에서 차단합니다.

## 최신 고증 수정

탐구1·2·4는 v4, 탐구3은 v5, 게임1~4는 v2 이미지를 사용합니다. 마지막 게임 맵의 전시판과 탐구4의 사각형 삽입 그림을 제거했습니다. 불국사 주변은 내륙 산림으로 정리하고, 칠지도는 좌우 세 가지가 위로 향하도록 수정했습니다. 바뀐 유물 위치에 조사 표시를 맞췄습니다. 기존 캐릭터 스프라이트는 유지합니다.

NPC와 조사 카드에 교과서 실물 사진 14개, 전체 21종 유물의 교과서 쪽수와 관찰 안내를 제공합니다. 생성 그림의 세부 명문·복식·건축 전체를 복원 검증한 것은 아닙니다. 수정 결과와 한계는 [교과서 검수 기록](history-textbook-audit.md), 최종 편집 지시는 [이미지 제작 기록](../assets/history/image-prompts-v5.md)에 있습니다.

테스트 8개·변경 파일 ESLint·프로덕션 빌드를 통과했습니다. 브라우저에서 탐구4와 수막새·은화 실물 사진 열기, 발해 2D 화면 진입을 확인했습니다. 추가 브라우저 검증에서 방향 버튼의 키보드 이동 → 주변 관찰 → 마을 사람 대화 → 자료 안내자의 수막새 실물 사진 열기를 확인했습니다. 창 포커스 이탈·탭 숨김 시 이동을 중지하고, 방향 버튼은 Enter/Space로 한 걸음씩 이동할 수 있게 보완했습니다. 전체 7단계 완주, 실제 Supabase 계정·동시 저장은 미검증입니다. 배포하지 않았습니다.
## 감정 이입 이야기

16개 경로에 창작 인물의 역할·도입 사건·NPC 대화·관점 전환·일기 질문을 연결했습니다. `lib/history/stories.mjs`에서 관리하며 게임과 텍스트 대체 흐름은 같은 이야기를 사용합니다. 교과서 사실은 별도 단서로 표시하고 감정을 정답으로 채점하지 않습니다. 여러 시대를 비교하는 경로는 탐구자의 장면 전환으로 구성하여 한 사람이 수백 년을 살거나 불국사와 청해진을 같은 장소로 오해하지 않도록 했습니다. 일기 화면에서도 도입과 마지막 질문을 다시 볼 수 있습니다.

검증: 16개 이야기와 7단계 연결 테스트를 추가해 전체 9개 통과. 변경 파일 ESLint와 프로덕션 빌드 통과. 브라우저에서 삼한 이야기의 역할·제목·도입과 창작 안내 표시를 확인했습니다. 새로운 이미지·애니메이션 의존성은 추가하지 않았습니다.

## 주제별 캐릭터 · NPC

학생 캐릭터 16종과 이름·직업이 다른 가상 NPC 32종을 연결했다. 큰 머리·작은 몸의 3D 로우폴리 그림체를 유지하며 머리카락·머리쓰개·복장·소지품을 구분한다. 실제 게임은 2D 스프라이트 방식이다. NPC의 지도 표식·대화창·텍스트 대체 흐름에 구체적인 이름과 역할을 표시하고, 직업별로 다른 조사 대사를 제공한다. 기록으로 확인된 실존 인물의 초상이나 실제 발언이라고 제시하지 않는다.

생성 원본의 체크무늬 제거와 프레임 정렬은 사용자 승인 아래 코드로 후처리했다. 최종 학생 시트 4장과 NPC 시트 2장만 런타임에서 사용하며, 처리 도구·모델은 학생 브라우저로 보내지 않는다. 모든 방향에 온전한 프레임이 있지만 일부 누락된 걸음은 같은 방향 프레임을 반복한다. 상세 출처와 제한은 `assets/history/character-prompts-v1.md`에 있다.

검증: 16개 학생 슬롯·32개 NPC 이름·이미지 크기·실제 투명 알파를 포함해 테스트 10개 통과. 전체 정면 모음과 추출 샘플을 이미지로 검수했다. 이번 에셋 교체 시 브라우저 연결이 없어 실제 조작 검증은 미완료다. 복식 전체 고증과 실제 학급 연결 검증도 여전히 남아 있다. 배포하지 않는다.

## 실행

- 개발: `node node_modules/next/dist/bin/next dev --port 3010`
- 실제 계정 진입: `/fieldtrip/history`. 기존 AuthProvider 및 Supabase 사용자 역할을 사용합니다.
- 개발 미리보기: `/fieldtrip/history/preview`. 가상 학생 16명, 실제 계정 기록 저장 없음. 개발 서버에서는 로그인 없이 열리며 프로덕션에서는 404입니다.
- Supabase 연결 코드에는 환경변수 참조만 있습니다. 현재 로컬에는 값이 없습니다. `.env.local.example`의 빈 항목을 로컬에서 설정하고 `supabase/history_init.sql`을 적용해야 합니다. 실제 키는 커밋하거나 채팅에 기록하지 않습니다.

## 화면 및 학습 흐름

- 창 전체를 사용하는 관찰 보드, 네 그림 동시 표시, 확대·이동·화면 맞춤.
- 3종 색상 메모지, 그림 위치와 연결선, 메모지 드래그·방향키 이동·삭제. 핀과 메모지 좌표를 각각 정규화해 보존합니다.
- 공개 전 자신의 관찰만 조회하고 교사 공개 후 같은 수업의 관찰을 조회합니다.
- 공동 조사카드 자동 저장·제출 버전·충돌 표시. 생성 그림은 실물 유물 사진을 대체하지 않습니다.
- 16개 경로 고정 배정, 개인 일기의 선택형 사실·자유 서술·힌트, 버전 고정 피드백과 대상 맵 승인.
- 교사 전체/선택 학생 강제 이동, 최신 명령 적용, 빈 제출 및 중단된 체험 보존, 로컬 초안·서버 버전 충돌 처리.

## 2D 전환과 이미지

- 3D 개인 체험을 2D 스프라이트 게임으로 교체했습니다. 이전 GLB와 Blender 원본은 보존하지만 신규 게임에서 불러오지 않습니다.
- `public/history/character-walk.png`: 기존 대머리·큰 다각형 머리·작은 몸 캐릭터를 고정한 투명 배경 4×4 스프라이트 시트. 아래·왼쪽·오른쪽·위 방향, 각 4프레임.
- `public/history/game-map-1-v2.png`~`game-map-4-v2.png`: 각 파일 2×2 배경 아틀라스, 총 16개 경로. SVG 도형으로 배경이나 캐릭터를 그리지 않습니다.
- 방향키/WASD, 화면 방향 버튼, 건물 영역 충돌, 가까운 대상과 E/버튼 상호작용, 단계별 단서. 이동 키가 눌린 동안만 프레임 갱신.
- 내부 활동 키 `3D`는 이전 저장 형식과 호환하기 위해 유지합니다. 화면에는 2D 체험으로 표시하고 새 진행 기록은 mode `2D`로 저장합니다.
- `public/history/exploration-1-v4.png`, `exploration-2-v4.png`, `exploration-3-v5.png`, `exploration-4-v4.png`: 기존 캐릭터를 유지하면서 시대별 환경·유물·상황을 구분한 새 탐구 그림. 확대해서 유물을 찾는 방식을 허용합니다.
- 생성 원본은 1536×1024 탐구/배경 이미지, 1254×1254 스프라이트입니다. PRD의 8192px 실물 조사 목표는 충족하지 않습니다.
- 프롬프트: `assets/history/image-prompts-v3.md`, `assets/history/game-image-prompts.md`. 수정 전 초안과 최종 사용 파일을 구분합니다.

## 검증 및 남은 작업

- 변경 기능 ESLint와 Next.js 프로덕션 빌드 통과. Supabase 환경변수 부재 경고는 남아 있습니다.
- 상태·메모 좌표·충돌·배정·권한·피드백·강제 이동과 16개 맵 이동 규칙 자료 참조 테스트까지 8개 통과.
- 기존 관찰 보드 메모 작성·이동·확대는 브라우저에서 검증했습니다. 2D 게임은 발해 경로에서 키보드 버튼 이동·NPC 대화·실물 사진 열기를 확인했습니다. 실제 학생 기기의 프레임 속도는 측정하지 않았습니다.
- 실제 Supabase 계정, SQL 적용, 16대 동시 저장, 명령 지연, 학생 기기 성능은 미검증입니다.
- 생성 이미지의 유물 형태·복식·건축·문양은 고증과 실물 자료 대조가 더 필요합니다. 옥저/동예·통일 과정 등 부족한 개별 조사 자료도 보완해야 합니다. 모든 경로의 ready=false를 유지합니다.
- 2D 배경은 교육용 재구성입니다. 그림 속 모든 세부 지형을 충돌 영역으로 추적하지 않으며 현재 주요 건물의 고정 충돌 영역만 적용합니다.
- 기존 앱은 단일 학급 명단 구조입니다. 교사 UUID를 학급 네임스페이스로, 차시별 UUID를 수업 ID로 사용합니다. 다학급·공동교사·보존/삭제 정책 추가 통합이 필요합니다.

## Git 및 배포 금지

사용자가 커밋·push를 요청하면서 배포를 금지했습니다. 기존 원격 커밋의 Vercel 배포 연결을 확인했습니다. 이번 작업 브랜치의 `vercel.json`에는 `git.deploymentEnabled: false`를 넣어 Git 자동 배포를 차단했습니다. 운영 브랜치에 병합하지 않으며 배포 명령도 실행하지 않습니다.

설정 근거: https://vercel.com/docs/project-configuration/git-configuration
